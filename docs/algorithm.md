# 알고리즘 설명 / Algorithm notes

ko-copycheck은 두 층으로 겹침을 찾습니다. 1층은 글자가 그대로 같은 구간(축자 일치), 2층은 표현을 바꿔도 문장이 비슷한 경우(바꿔 쓰기)입니다.

## 1층 — winnowing (Schleimer, Wilkerson, Aiken 2003)
**문제**: 글 두 편을 글자마다 대 보면 편수가 늘수록 너무 오래 걸립니다. 각 글에서 "대표 지문"만 뽑아 같은 지문을 가진 글끼리만 비교하고 싶습니다.

**1) k-gram**: 정규화한 글에서 연속 k글자(기본 8)를 모두 자르고 해시합니다.
**2) 창에서 최솟값 선택**: 해시 w개(기본 4)짜리 창을 한 칸씩 밀며 창마다 가장 작은 해시를 골라 `(해시, 위치)`를 지문으로 둡니다(같으면 오른쪽).
**3) 보장**: 두 글에 길이 `w + k - 1`(= 11)글자 이상 같은 구간이 있으면 그 안에 해시 w개가 모두 같은 창이 있으므로 두 글은 같은 지문을 반드시 하나 고릅니다. 11글자 미만은 놓칠 수 있습니다.

실제로 실행한 작은 예(`kgram_hashes`, `winnow`, 20글자 문장):
```text
정규화 글자 수 20, 8-gram 13개
선택된 지문 위치: [1, 2, 5, 6, 7, 9]
```
13개 중 6개만 남습니다. 지문이 같은 문서 쌍을 후보로 삼은 뒤 앞뒤로 글자를 비교하며 구간을 넓혀 실제 일치 길이를 잽니다(최소 20글자).

**왜 글자 단위인가**: 한국어는 조사·어미가 붙어 어절이 쉽게 달라집니다("지역이" / "지역보다"). 글자 조각은 어절 하나가 달라져도 나머지 조각은 살아 있습니다.

**왜 안정 해시인가**: 파이썬 내장 `hash()`는 실행마다 값이 달라집니다. blake2b로 만든 8바이트 값은 프로세스가 달라도 같습니다.

### 과제 문구와 공통 구절
모두가 인용하는 과제 문구가 겹침으로 잡히면 쌍마다 점수가 올라갑니다. `--prompt` 파일과 같은 글자 구간은 마스킹해 두 글에서 모두 빼고, 점수 분모에서도 뺍니다. 또 모든 k-gram의 문서 빈도를 세어 문서의 50% 이상이면서 3편 이상이 공유한 구절은 공통으로 제외합니다. 지문이 아니라 모든 k-gram의 빈도로 세는 이유는, 지문만 세면 한 글에서는 선택되고 다른 글에서는 안 된 경계 조각 때문에 공통 구절이 되살아나기 때문입니다.

## 2층 — 문장 글자 bigram Dice
문장을 글자 2개짜리 조각(bigram)의 집합으로 바꾸고 Dice 계수로 비교합니다.

`Dice(A, B) = 2 × |A ∩ B| / (|A| + |B|)`

실제로 계산한 예(`paraphrase.dice`):
```text
도시 열섬 현상은 도심의 기온이 주변 교외 지역보다 높게 나타나는 현상을 말한다
도시의 열섬 현상은 도심 온도가 교외 지역보다 높아지는 현상이다
  bigram 31개와 25개, 공통 14개 → Dice 0.50

도시 열섬 현상은 도심의 기온이 … 말한다
여름철 열대야가 길어지면 노약자의 온열 질환 위험이 커진다
  bigram 31개와 24개, 공통 0개 → Dice 0.00
```
기본 기준 0.30 이상이면 "바꿔 쓴 문장"으로 표시합니다.

**접두 필터**: 문장 수만 개를 전부 짝지으면 수억 번 비교해야 합니다. Dice가 기준 t 이상이려면 겹치는 bigram이 최소 몇 개는 있어야 하므로, 문장의 bigram을 드문 것부터 세웠을 때 앞쪽 몇 개 중에 공유 bigram이 반드시 있습니다. 이 앞쪽(접두)을 공유하는 문장끼리만 비교합니다. 결과는 전수 비교와 같습니다(테스트로 확인). 문서 300편×3000자 실험에서 문장 비교는 약 164만 번으로, 전수 비교 약 3.99억 쌍보다 크게 적었습니다(`scripts/bench.py`).

## 점수
- 축자 일치: 일치 구간이 덮는 글자 / (문서 글자 − 마스킹 글자)
- 종합: 왼쪽 글 기준으로 (축자 일치 구간 ∪ 바꿔 쓴 문장 구간)이 덮는 글자 / 같은 분모
